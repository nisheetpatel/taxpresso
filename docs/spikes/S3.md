# Spike S3: extension shell

Question: can Taxpresso ship as a `.mcpb` extension for Claude Desktop that runs our local server on the Node runtime Claude provides, shows a dashboard on 127.0.0.1, renders inline where the host supports MCP Apps, and gets Claude to follow our server instructions?

Status (13 October 2026): built and tested automatically. Installed in Claude Desktop on the human's Mac: it installs and the dashboard opens. The other checks below are still open. Provisional verdict: **go**. Nothing found so far blocks the architecture in SPEC.md section 3.

## What was built

`build/taxpresso-0.0.2.mcpb` (about 460 KB). Rebuild it with `pnpm install && pnpm build:mcpb`.

| Part | What it is |
|---|---|
| `manifest.json` | mcpb manifest v0.3 (the version your installed Anthropic extensions use). `user_config`: `vault_path` (directory, default `~/Documents/Taxpresso`), `ui_language` (`en` or `fr`). |
| `server/index.mjs` | The MCP server `taxpresso`, one esbuild bundle, no `node_modules`. Contains only `@modelcontextprotocol/server` 2.3.1, `@modelcontextprotocol/core` 2.3.1 and `zod`. |
| Tools | `get_status` (read-only; `detail: true` adds the Node runtime) and `open_dashboard` (read-only; starts the dashboard and returns its private link). Both carry `title`, `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`. |
| Prompt | `start_geneva_tax_return`, "Start my Geneva tax return". |
| Server instructions | `extension/src/instructions.ts`, SPEC.md section 14 trimmed to the two tools. |
| Dashboard | `ui/dashboard/` (Vite build, Geist fonts bundled). Served on `127.0.0.1:<random port>` with a per-session token; English and French. |
| MCP Apps view | `ui://taxpresso/open-dashboard.html`, attached to `open_dashboard`: an inline card with an "Open dashboard" button. |

## Findings so far

- Claude Desktop on this Mac is 2.31226.1, on Electron 44.4.3, which embeds **Node v24.21.0**. If Claude runs extensions on its built-in Node, that is our runtime. CI tests Node 22 and 24. Check 4 below confirms which Node actually runs.
- MCP TypeScript SDK v2 splits server and client into separate packages. The server package depends only on `zod` and `core`, so no HTTP client code reaches the bundle. v1 (`@modelcontextprotocol/sdk`) pulls in express, hono, cors, eventsource and jose. Decision: use v2.
- The SDK's `serveStdio` handles both the 2025 protocol versions (Claude Desktop today) and 2026-07-28 from the same server code.
- mcpb `user_config` has no enum type, so `ui_language` is a free string. The server accepts `en` or `fr` and treats anything else as `en`.
- `license_key` is left out of `user_config` until licensing goes live for tax year 2027: TY2026 has no license checks (SPEC.md section 12), and an empty "License key" field at install would make people think they need one. SPEC.md section 11 now says so.
- The MCP Apps card is 590 KB, because the official `@modelcontextprotocol/ext-apps` client brings zod with it. That is fine for a spike. Before launch: a small hand-written postMessage bridge, tested against ext-apps' `AppBridge`.
- The extension does not create the Taxpresso folder yet. It only reports whether it exists (vault work comes with the ledger). When it does, it must refuse a folder inside a git repository: on a developer's Mac, `~/Documents/taxpresso` (the code) and `~/Documents/Taxpresso` (the tax folder) are the same folder, because macOS ignores case. That is why the repo lives in `~/Documents/taxpresso-app`.
- `manifest.json` author is a placeholder ("Taxpresso") until the legal entity is decided (SPEC.md section 18).
- Default stays `.mcpb` plus server instructions. A plugin with a skill is only worth the extra install step if check 2 or 3 shows Claude ignoring the instructions.

## Install it in Claude Desktop (exact steps)

To update an earlier version: **Settings > Extensions > Taxpresso > Uninstall**, then install the new file. Your answers and documents stay in your Taxpresso folder.

You need Claude Desktop on macOS or Windows, signed in. Nothing here needs network access from the extension.

Two folders, never the same one:

- `~/Documents/taxpresso-app` is the **code** (this repo). The file you install is in it.
- `~/Documents/Taxpresso` is **your tax folder**, where Taxpresso will keep your documents. It must never be inside the code folder, so that no real tax document can end up in git. You don't need to create it now.

1. In Finder, open **Documents > taxpresso-app > build**. The file is `taxpresso-0.0.2.mcpb`. If it's missing, run this in Terminal, then look again:

   ```bash
   cd ~/Documents/taxpresso-app && pnpm install && pnpm build:mcpb
   ```

2. Open Claude Desktop, then **Settings** (Cmd+, on Mac) and go to **Extensions**.
3. Install the file in one of these ways, and note which one worked:
   - a. At the bottom of Extensions, open **Advanced settings**. Under **Extension Developer**, click **Install Extension…** and pick `taxpresso-0.0.2.mcpb`.
   - b. Drag `taxpresso-0.0.2.mcpb` from Finder onto the Extensions page.
   - c. Double-click `taxpresso-0.0.2.mcpb` in Finder.
4. In the install dialog, check that it shows "Taxpresso", the icon (white check on a dark square), the two tools and the prompt. Click **Install**.
5. Configure:
   - **Taxpresso folder**: keep the default, `Documents/Taxpresso`. Don't pick `taxpresso-app` or anything inside it: Taxpresso refuses a folder inside a code repository. Since 0.0.2 the folder is optional at install and Taxpresso creates it with your first answer; if the installer still refuses, create it in Finder (**Documents**, then **File > New Folder**, name it `Taxpresso`) and pick it.
   - **Dashboard language**: `en` or `fr`. Try `fr` once to check the French page.
   - Save, and make sure the Taxpresso extension is switched on.
6. Under **Advanced settings**, write down what it says about Node.js (for example "Use built-in Node.js for MCP" and the detected version).

## Checks to run (record each result in the table at the end)

Start a **new chat** for each numbered check, so earlier answers don't influence the next one.

1. **Tools visible.** Open the tools menu in the chat input (the sliders or "+" icon). Taxpresso should be listed with `get_status` and `open_dashboard`.
2. **Instructions respected.** Type: `Can you help me with my taxes this year?` Expected: Claude calls `get_status` (you see the tool call) before it answers, and mentions the dashboard as the next step.
3. **No tax facts from memory.** Type: `How much can I pay into my pillar 3a in 2026?` Expected: Claude does **not** give a number from its own knowledge. It should say this version has no tax engine yet. Write down exactly what it says; this is the hardest instruction to follow.
4. **Runtime.** Type: `Call get_status with detail and tell me the Runtime line.` Expected: `Node v24.x`, and a path inside `Claude.app` if Claude uses its built-in Node, or a system path such as `~/.nvm/...` or `/opt/homebrew/...` if not. Record the full line.
5. **Dashboard and MCP Apps.** Type: `Open my Taxpresso dashboard.`
   - a. Claude calls `open_dashboard` and gives a link like `http://127.0.0.1:53124/?t=...`.
   - b. **MCP Apps:** does an inline card appear in the chat with an "Open dashboard" button? If so, click it. Where does the page open (Claude's browser pane, your default browser, nowhere)?
   - c. **Browser pane:** ask `Open that link in your browser pane.` Can Claude open 127.0.0.1 in its own browser inside Claude Desktop? Record yes or no, and whether it asked for permission.
   - d. Click the link in the chat. Expected page: "Your Taxpresso dashboard", tax year 2026, and your folder path, marked "Found" if the folder exists or "Not created yet" if not.
6. **One state, two views.** With the dashboard visible, ask Claude in the same chat: `What's my Taxpresso status?` Within 2 seconds the dashboard's "Activity from the chat" should show "Claude checked where you are".
7. **Prompt.** Find "Start my Geneva tax return" (in the "+" menu, or wherever Claude Desktop lists extension prompts). Record where it appears and what happens when you pick it.
8. **Clean exit.** Quit Claude Desktop completely (Cmd+Q). Within a few seconds the dashboard tab should say "Taxpresso is not answering". Then run this in Terminal; it should print nothing:

   ```bash
   pgrep -fl "server/index.mjs"
   ```

9. **[HUMAN] Who can install.** Repeat install steps 2 to 5 on a **Free** account and on a **Pro** account (sign out and in again, or use another computer). Record for each plan whether **Settings > Extensions** exists and whether installing from a file works. This decides who the product can reach.
10. **Optional, Windows.** The same install and checks 1 to 6 on Windows, if you have a machine.

If something fails, the server log is here (macOS):

```bash
ls ~/Library/Logs/Claude/
```

```bash
tail -n 50 ~/Library/Logs/Claude/mcp*.log
```

On Windows the logs are in `%APPDATA%\Claude\logs`. The extension writes only errors to that log; it never logs document contents.

To uninstall: **Settings > Extensions > Taxpresso > Uninstall**. The extension never created files outside its own install folder.

## Go / no-go

Provisional: **go** on the automated evidence. It becomes final once checks 1, 2, 4, 5d and 9 pass.

- No-go conditions: Pro accounts can't install a `.mcpb` from a file (the product would only reach Team and Enterprise), or Claude Desktop can't run the extension at all.
- If check 5b fails (no inline card): not a blocker. The localhost page is the full fallback (SPEC.md section 3).
- If check 5c fails (Claude's browser can't open 127.0.0.1): not a blocker for the dashboard (the user clicks the link). It matters for S1 (filing in Claude's browser) only if the pane can't open ge.ch either.
- If check 2 or 3 fails: try a stronger instruction wording first, then a plugin with a skill.
